The path of a write

one PUT, five stages, no leader.

01 / route

Place

The ring hashes the key and returns its N replica nodes. A red-black tree over virtual nodes keeps placement balanced as the cluster grows.

02 / fan out

Replicate

The coordinator writes to all replicas and waits for W acknowledgments. A sloppy quorum walks past down nodes so a write is never blocked.

03 / persist

Durably log

Each replica appends to a CRC-checked WAL, with fsyncs batched across writers by group commit, then flushes its memtable to bloom-filtered SSTables.

04 / version

Reconcile

Vector clocks track causality. Concurrent writes surface as siblings for the client to merge, rather than one silently overwriting the other.

05 / heal

Converge

Read repair fixes stale replicas inline; hinted handoff replays missed writes; Merkle-tree anti-entropy is the slow, thorough backstop.

Reads run the same ring in reverse: fan out to the replicas, wait for R responses, merge siblings, and repair any replica that came back stale. Clients that need more can opt into linearizable conditional writes, each a per-key Paxos round, or a session clock for read-your-writes.

built to be read, and to be built on.

The whole point of Continuum is legibility: every headline number links to a benchmark, every design choice links to the document that defends it. Contributions are welcome. The docs are plain Markdown and the test pyramid runs from unit seams up through process-level fault injection, so a change is easy to make and easy to trust.
